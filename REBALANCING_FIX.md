# Rebalancing liquidity fix — 15 November 2026

## Problem fixed

The former quarterly rebalancing code could try to buy additional illiquid holdings
when PE, venture capital and, in stressed quarters, hedge funds were locked.
In extreme market paths the combined minimum locked allocation could exceed total
endowment wealth. The code then clipped the amount allocated to movable assets
to zero, without reducing the locked purchase targets, and tried to pay trading
costs from nonexistent liquid assets. The entire 5,000-path simulation aborted
with `Insufficient liquid holdings to fund quarterly rebalancing costs.`

## Revised trading algorithm (`investment_model.py`)

1. Calculate the usual quarterly target weights and private-sleeve pacing.
2. Maintain the no-sale restriction for locked PE/VC and the applicable hedge
   fund lock, plus exact holding freezes for restricted EM/high-yield holdings.
3. Limit any *purchases* of locked investments to existing unencumbered movable
   asset value; preserve the total pre-fee value of the portfolio.
4. Calculate the proposed rebalancing cost using the **actual asset-specific
   transaction-cost rates**.
5. If the liquid fee-paying holdings cannot cover the proposed cost, execute
   only an affordable fraction of the proposed trades. The executed trade
   fraction is solved from its linear cost and post-trade cash constraints:

       fraction * full_trade_cost
          <= opening_fee_payer_wealth + fraction * change_in_fee_payer_wealth

   If no positive trade fraction is affordable, **defer this quarter's trade**.
6. Deduct costs **only on trades actually executed**, from unlocked eligible
   holdings, then apply simulated market returns and continue annual payout
   calculations normally.

This does not mint cash, sell locked assets, erase expenses, or treat failed
rebalancing as an unpaid university payout. The actual holdings can drift from
target allocations when liquidity prevents rebalancing; subsequent returns and
payouts use these actual holdings. The maximum 5-percentage-point quarterly
private reallocation pacing is retained.

## Economic interpretation

The inability to rebalance to target allocations is a *portfolio implementation
constraint*. It does not prove a university payout failed. A change in the
realized return distribution is possible versus a model that forced portfolio
weights back to target at all times; compare results after rerunning. The
financial assumptions, spending rules, gift restrictions, asset-sale deadlines,
capital calls and reserve policies have not otherwise been changed.

For the user-facing analysis, choose **Private / Base**, check **Compare the
three main strategies**, choose **5,000 paths**, and click **Run analysis**.
Repeat for Public/Base. A very adverse path should now yield a constrained
trade or no trade for that quarter, not stop the entire analysis.

## Audit caution

Any files supplied in `validation_output/` with timestamps preceding this fix
were generated by the previous version and are **not** proof that the corrected
code has passed every production scenario. New validation runs should be labeled
with their institution, path count, strategy set and version. A pass of Python
unit tests does not establish economic calibration.
